# Публикация Owl Smile в магазинах расширений

Состояние на 13.11.2026. Сейчас расширение ставится из zip в режиме разработчика (README). Здесь — что нужно, чтобы выложить его в магазины, и что для этого поменять в коде. Решение о публикации не принято.

## Куда выкладывать

| Магазин | Кто сможет поставить | Цена | Особенности |
|---|---|---|---|
| **Chrome Web Store** | Chrome, Яндекс Браузер, Edge, Opera (через их настройки) | разовый взнос при регистрации (исторически $5) | главный вариант: один листинг закрывает почти всех |
| Microsoft Edge Add-ons | Edge | бесплатно | нужен аккаунт Microsoft (Partner Center), проверка до 7 рабочих дней |
| Opera Add-ons | Opera, Яндекс Браузер | бесплатно | код без минификации или ссылка на исходники с инструкцией по сборке; очередь проверки бывает неделями |

**Рекомендация:** один листинг в Chrome Web Store с видимостью **«По ссылке» (Unlisted)**. Его не найти в поиске, но поставить по прямой ссылке может кто угодно. Требования и проверка такие же, как у публичного. Яндекс Браузер официально ставит расширения только из каталогов Chrome и Opera, так что Chrome Web Store его покрывает. Edge тоже ставит из Chrome Web Store (после «Разрешить расширения из других магазинов»).

Плюс по сравнению с zip: обновления приходят сами, не нужно включать режим разработчика, браузер не предупреждает о «расширениях разработчика».

## Регистрация в Chrome Web Store

1. Аккаунт Google для разработчика. **Почту аккаунта потом не сменить** — лучше отдельный ящик для проекта.
2. Принять соглашение разработчика, оплатить разовый взнос (сумма — в кабинете при регистрации).
3. Подтвердить почту, указать имя издателя (видно под «Offered by»). Физический адрес не нужен: расширение ничего не продаёт.
4. Россия в списке поддерживаемых стран есть, но для оплаты нужна карта, которую примет Google.

Новым издателям сначала разрешено не больше двух опубликованных расширений.

## Что заполнить в кабинете

**Вкладка «Конфиденциальность» (Privacy):**

- **Единственная цель:** «Показывает в чатах Twitch и VK Live общие смайлы, иконки у ников и эффекты ников из базы Owl Smile и позволяет загружать в неё новые».
- **Обоснования разрешений** — по одному на каждое:
  - `storage` — кэш базы смайлов и настройки;
  - `unlimitedStorage` — картинки смайлов хранятся локально (data URL), база растёт;
  - `alarms` — синхронизация базы раз в 15 минут;
  - `scripting` — подключить скрипт к уже открытым вкладкам Twitch и VK Live сразу после установки или обновления;
  - `https://gitflic.ru/*` — чтение и запись базы;
  - `https://*.twitch.tv/*`, `https://live.vkvideo.ru/*` — показ смайлов в чате.
- **Удалённый код:** «Нет». Код не загружается, из сети приходят только JSON (проверяется zod) и картинки.
- **Собираемые данные** (с 1 августа 2026 сбор данных надо раскрывать весь, даже если он нужен для работы):
  - *Authentication information* — ключ доступа: хранится в браузере и отправляется на gitflic.ru;
  - *Personally identifiable information* — ник загрузчика попадает в общую базу (подпись коммита) и ники зрителей в `users/…`, если им назначили иконки.

  Содержимое чата не собирается и никуда не отправляется: скрипт только заменяет коды на картинки на месте.
- **Политика конфиденциальности (URL)** — по сути обязательна: расширение передаёт ключ доступа и публикует ники. Хватит одной страницы, например `docs/privacy.md` в репозитории кода на GitFlic с публичной ссылкой. В ней:
  - что хранится локально (кэш базы, ключ, ник);
  - что уходит на gitflic.ru (запросы базы; ключ и ник при загрузке);
  - что публикуется в общей базе (картинки, коды, ник загрузчика, ники зрителей с иконками);
  - как удалить: выйти и стереть ключ на странице загрузки, удалить расширение, попросить владельца убрать запись из базы.

**Листинг:**

- Иконка 128×128 (рисунок 96×96 с прозрачными полями по 16 px). Сейчас 128.png — сова во весь размер, нужно добавить поля.
- Минимум 1 скриншот 1280×800 или 640×400 (лучше 3–5): чат Twitch со смайлами, чат VK Live, окно смайлов, страница загрузки.
- Маленькая промо-плитка 440×280 — необязательна, но без неё листинг ниже в выдаче (для «По ссылке» неважно).
- Описание на русском. Английское — по желанию: тогда понадобятся `_locales`.

**Проверка:** обычно несколько дней, иногда до нескольких недель. Новый издатель, `scripting` и три адреса хостов могут её затянуть. После одобрения есть 30 дней, чтобы нажать «Опубликовать».

## Что поправить в коде до отправки

1. **`Function(...)` в сборке.** В `background.js` и `manage-*.js` есть два вызова конструктора `Function`:
   - проверка `Function('')` из zod — в MV3 она молча ловит ошибку CSP;
   - `Function('binder', …)` из полифила `function-bind`, который тянет одна из зависимостей.

   Вреда нет, но проверяющие на такое реагируют. Что сделать:
   - у zod включить `z.config({ jitless: true })`;
   - найти, кто тянет `function-bind` (`npm ls function-bind`), и заменить зависимость или подставить нативный `Function.prototype.bind` через alias в `wxt.config.ts`.
2. **Иконка 128** — добавить прозрачные поля (см. выше).
3. **`homepage_url`** в манифесте — ссылка на страницу проекта на GitFlic.
4. **Политика конфиденциальности** — страница и ссылка на неё (см. выше).
5. **Версия и упаковка:**
   - для магазина нужен zip из `npm run zip` (`.output/owl-smile-X.Y.Z-chrome.zip`), его загружают в кабинет вручную;
   - `npm run release` (релиз на GitFlic) можно оставить параллельно для установки из zip.
6. **Ключ магазина.** У расширения из магазина будет другой ID, чем у распакованного. Ключ доступа и настройки не перенесутся: друзьям, переходящим с zip, придётся ввести ключ заново и удалить старую версию, иначе будет две совы.

## Риски

- **Общий ключ записи.** У всех, у кого есть ключ, равные права на базу. Для магазина это не нарушение: ключ вводит сам пользователь, в сборке его нет (это проверяет `scripts/release.ts`). Но в политике конфиденциальности это стоит описать честно.
- **Вёрстка площадок меняется.** Twitch и VK переделывают чат. Сломанные селекторы — не повод для снятия с магазина, но обновления придётся проводить через проверку, а это дни, а не минуты как с zip.
- **Opera:** код собран Vite и минифицирован. Для Opera Add-ons понадобится ссылка на исходники и инструкция по сборке (`npm ci && npm run build`), либо сборка без минификации.
