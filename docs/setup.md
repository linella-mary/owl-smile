# Owl Smile — настройка, сборка и релизы (для владельца)

Инструкция для друзей — в [README.md](../README.md).

## Как устроено

| Что | Где | Доступ |
|---|---|---|
| Код расширения и релизы (zip) | проект GitFlic `ju1iana/owl-smile` | публичный |
| Смайлы, иконки, эффекты | проект GitFlic `ju1iana/owl-smile-data` | публичный на чтение, запись — по ключу |
| **Ключ доступа** (токен развёртывания `owl-smile-data`) | только у вас и у друзей, которые загружают | передаётся лично, **в сборку не попадает** |
| Личный API-токен GitFlic | только у вас в `extension/.env` | нужен для `npm run release` |
| Ключи API addons.mozilla.org | только у вас в `extension/.env` | подпись версии для Firefox |

## 1. Репозиторий данных `owl-smile-data` (уже настроен)

1. Публичный проект, ветка `master`, начальные файлы залиты командой `npm run seed`.
2. Токен развёртывания с правом записи хранится в `extension/.env` → `GITFLIC_DEPLOY_TOKEN`. Он же — **ключ доступа** для друзей.
3. Защита ветки: «Настройки → Защищённые ветки» → правило для `master`: push для роли «Разработчик», **«Разрешить push --force» выключено**.

**Смена ключа**, если он утёк:
1. Удалите старый токен развёртывания и создайте новый.
2. Пропишите новый токен в `.env`.
3. Разошлите его тем, кто загружает. Им нужно нажать «Сменить ключ» на странице загрузки.

Пересобирать расширение не нужно.

## 2. Проект с кодом `owl-smile` и релизы

Один раз:
1. Создайте на GitFlic **публичный** проект `owl-smile` — пустой, без README.
2. Личный API-токен («Профиль → API токены» — именно в профиле, а не в настройках проекта) → `extension/.env` → `GITFLIC_API_TOKEN`. Им создаются релизы.
3. Токен развёртывания проекта `owl-smile` → `GITFLIC_CODE_DEPLOY_TOKEN`. Им скрипт пушит код и теги.

Сделано: код в `master`, теги `v0.1.0` и `v0.1.1`, релиз `v0.1.1` с архивом. Архив скачивается без входа на GitFlic по ссылке вида `…/release/<id релиза>/<id файла>/download` (проверено).

Если git ругается на «dubious ownership»: `git config --global --add safe.directory D:/_DEV/owl_smile`.

Каждый релиз:
```bash
cd extension
npm run release -- 0.2.0 "Что нового в этой версии"
```
Скрипт ставит версию, собирает zip, проверяет, что ни один токен из `.env` не попал в сборку, ставит тег `v0.2.0`, пушит код и создаёт релиз с файлом `owl-smile-0.2.0.zip`.

### Версия для Firefox

Firefox ставит насовсем только дополнения, подписанные Mozilla. Подписываем без публикации в каталоге (канал *unlisted*): Mozilla проверяет файл автоматически, обычно за несколько минут, а раздаём его сами — в релизах GitFlic рядом с zip.

Один раз:
1. Зарегистрируйтесь на [addons.mozilla.org](https://addons.mozilla.org) (аккаунт Mozilla).
2. В Центре разработчиков меню **«Инструменты»** справа вверху → **«Управление ключами API»** (или сразу <https://addons.mozilla.org/ru/developers/addon/api/key/>) → примите соглашение, если спросят → **«Сгенерировать новые учётные данные»**. Загружать дополнение через «Отправить новое дополнение» не нужно: это делает скрипт.
3. Впишите в `extension/.env`: `AMO_JWT_ISSUER` (издатель JWT) и `AMO_JWT_SECRET` (секрет JWT). Секрет никому не показывайте: с ним можно выпускать версии от вашего имени.

После этого `npm run release` сам собирает версию для Firefox, проверяет её и исходники на токены, подписывает и прикладывает к релизу `owl-smile-X.Y.Z-firefox.xpi`. Без этих ключей релиз выходит только для Chrome. Подписать отдельно, без релиза: `npm run sign:firefox`.

Важно:
- **Одну версию Mozilla подписывает один раз.** Если подпись прошла, а релиз сорвался, выпускайте следующую версию.
- **id дополнения** `owl-smile@gitflic.ru` задан в `wxt.config.ts`. Его нельзя менять: Firefox посчитает новую версию другим дополнением.
- Mozilla получает и **архив исходников** (`owl-smile-X.Y.Z-sources.zip`, без `.env`), потому что код в сборке склеен в общие файлы. Если проверяющие попросят собрать сами: Node 22+, `npm ci`, файл `.env` с переменными `WXT_GITFLIC_*` (они публичные), затем `npm run build:firefox`.
- Firefox-сборка — Manifest V2 (у WXT это по умолчанию для Firefox): доступ к сайтам выдаётся при установке, в MV3 его пришлось бы включать вручную.
- Проверить без подписи: `npm run build:firefox` → `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» → `extension/.output/firefox-mv2/manifest.json`. Временное дополнение пропадает после перезапуска Firefox.

## 3. Файл `extension/.env`

См. `.env.example`.
- Переменные `WXT_*` попадают в сборку. Это не секреты: адрес и логин публичного репозитория.
- `GITFLIC_DEPLOY_TOKEN`, `GITFLIC_API_TOKEN` и `GITFLIC_CODE_REPO` используются только скриптами на вашем компьютере.

### Админ страницы загрузки

Админ один. Без входа админа на странице загрузки доступна только вкладка «Смайлы»: добавлять смайлы, удалять и переименовывать свои (свои — подпись автора совпадает с ником вверху страницы). Иконки, эффекты, подложки, оформление зрителей и чужие смайлы — только админу.

1. `npm run admin:key -- <ник админа>` — печатает личный ключ админа и две строки для `.env` (`WXT_ADMIN_NICK`, `WXT_ADMIN_KEY_SHA256`).
2. Ключ сохраните у себя и никому не пересылайте. В `.env` и в сборку попадает только его отпечаток.
3. Впишите строки в `extension/.env` и выпустите новую версию.
4. На странице загрузки: «Вход админа» → ник и ключ. Вход запоминается на этом компьютере; «Админ · выйти» его забывает.

Новый ключ — снова `npm run admin:key` и новый выпуск: старый ключ перестанет подходить.

Пустые `WXT_ADMIN_*` — админского режима нет, все, у кого есть ключ доступа, могут всё (как до версии 0.6.1).

Это защита от случайных правок, а не от умысла: ключ доступа даёт право записи в репозиторий, и его владелец может изменить базу обычным git в обход расширения. Откатить такое можно по истории git (держите запрет `push --force` на ветке `master`).

## 4. Проверки

| Команда | Что делает |
|---|---|
| `npm test` | юнит- и интеграционные тесты (локальный git-сервер ведёт себя как GitFlic). Запускается через `scripts/vitest.mjs`: в Windows vitest ломается, если папка открыта как `d:\…` |
| `npm run e2e` | Chromium с расширением: синхронизация, чат Twitch, пикер, Tab, ключ, вход админа, загрузка |
| `npm run e2e:obs` | Chromium изображает док OBS: окна входа VK и Twitch закрываются сами, ссылки — нет, док закрыть нельзя |
| `npm run spike:gitflic` | Node ↔ настоящий GitFlic: чтение, push, гонка, очистка |
| `npm run build` + `npm run check:live -- --write` | рабочая сборка в Chromium ↔ настоящий GitFlic: синхронизация, неверный и верный ключ, загрузка и удаление |
| `npm run check:release-api -- vX.Y.Z файл.zip` | API релизов: пре-релиз на теге без релиза → загрузка → скачивание без входа → удаление |
| `npm run compile` | проверка типов |
| `npm run dev` | WXT dev-режим с автоперезагрузкой |

E2E собирает отдельную тестовую сборку в `.output-e2e`. Рабочую `.output` она не трогает.

## 5. Бэкап данных

Удаление ветки защитить нельзя. Поэтому периодически сохраняйте зеркало:

```bash
git clone --mirror https://gitflic.ru/project/ju1iana/owl-smile-data.git   # первый раз
cd owl-smile-data.git && git remote update                                  # потом
```
