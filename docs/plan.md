Отличия от исходного плана:
- переменные окружения с префиксом `WXT_` (требование WXT);
- у синхронизации и записи разные базы LightningFS, чтобы фоновый скрипт и страница не писали в одно хранилище;
- коды смайлов уникальны без учёта регистра: иначе на Windows конфликтуют имена файлов `CatJam.json` и `catjam.json`;
- MutationObserver смотрит за `document.body` и фильтрует по селектору сообщения — так надёжнее при SPA-навигации.

Особенности GitFlic, найденные на этапе 0.1 (учтены в коде, тестовый сервер их повторяет):
- git-протокол **v2** → 401, работает только **v1**. `fetch` и `push` в isomorphic-git и так используют v1.
- `POST` без заголовка `User-Agent` → 401. Клиент isomorphic-git для Node его не ставит → `withUserAgent` в `repo.ts`.
- push без авторизации → 401 с `WWW-Authenticate`, и браузер показывает своё окно ввода пароля, а запрос зависает → авторизация отправляется сразу в заголовке.
- Логин для токена развёртывания — псевдоним владельца (`ju1iana`).

Как запускать и собирать — см. [setup.md](setup.md).

## Контекст

Нужен закрытый сервис кастомных смайлов, иконок у ников и эффектов ников для своей компании.
Компоненты: браузерное расширение (Chrome/Edge/Яндекс) и общее хранилище на **GitFlic**.
Загружать может любой, у кого есть расширение: доверяем всем. Сейчас в папке проекта лежит только `задание.md`, код пишем с нуля.

**Что проверено при анализе (меняет предложенное в задании решение):**
- В REST API GitFlic **нет эндпоинтов записи файлов**, только GET. Есть лимит 500 запросов в час на токен. Код из задания (`POST/PUT .../file`) работать не будет.
- В документации **нет формата raw-ссылки** на файл, поэтому `blob/raw?file=...` ненадёжен.
- Писать в GitFlic можно только **через `git push` по HTTPS**. Решение пользователя: делать push прямо из расширения через `isomorphic-git`.
- Для этого подходят **токены развёртывания проекта** (deploy token): `https://<alias>:<token>@gitflic.ru/project/<owner>/<repo>.git`. Такой токен ограничен одним проектом, поэтому безопаснее аккаунтного API-токена.
- В защищённой ветке можно запретить `push --force` и оставить обычный push. Защиту от удаления ветки документация не описывает.
- Статьи по ссылкам из задания почти не пригодятся. На Habr — расширение Image Grabber без работы с чатом. Справка Google описывает создание расширения и публикацию в Chrome Web Store, в том числе режим «Доступ по ссылке».

## Ключевые решения

1. **Хранилище — публичный репозиторий GitFlic `owl-smile-data`.**
   - Чтение: `isomorphic-git` делает `fetch` без авторизации, неглубокий (`depth: 1`, `singleBranch`). Не зависим от недокументированных raw-ссылок и лимита REST API.
   - Запись: тот же `isomorphic-git` делает `push` с deploy-токеном.
   - Гонки при одновременной загрузке решает сам git: если push отклонён как не fast-forward, делаем fetch, заново применяем операцию и повторяем, до 3 раз.
2. **Данные лежат по файлу на сущность, без общего `emotes.json`.** Так меньше конфликтов. Уникальность кода проверяется естественно: файл `emotes/<code>.json` уже существует — значит, код занят.
3. **Синхронизация в фоне расширения.**
   - Когда: при `chrome.runtime.onStartup` и `onInstalled`, раз в 15 минут через `chrome.alarms`, по кнопке «Синхронизировать» и сразу после своей загрузки.
   - Если хеш HEAD не изменился, ничего не делаем.
   - Если изменился, перечитываем дерево. Картинки, которых ещё нет в кэше, кладём в `chrome.storage.local` под ключом `img:<git blob oid>`. Лишние удаляем.
   - Если сервис-воркеру MV3 не хватает времени жизни, git-операции переносим в offscreen-документ.
4. **Чат не ходит в сеть.** Content script читает `chrome.storage.local` напрямую, создаёт `blob:` URL (или `data:` URL, если CSP площадки не пускает `blob:`) и подставляет картинки.
5. **Безопасность при модели «доверяем всем».**
   - Токен ограничен одним проектом. В защищённой ветке force-push запрещён.
   - Владелец периодически делает `git clone --mirror` как бэкап: удаление ветки защитить нельзя.
   - Данные из репозитория **никогда** не попадают в `innerHTML` и в сырой CSS. Все JSON проверяются схемами zod. Эффекты ников — только пресеты из белого списка, цвета строго `#RRGGBB`.
6. **Назначать иконки и эффекты может любой** (решение пользователя). Владение ником не проверяется. Откат через историю git.
7. **Стек:** WXT (фреймворк для MV3) + TypeScript + Vite, `isomorphic-git` + `@isomorphic-git/lightning-fs`, zod, Preact для страниц расширения и пикера, vitest, Playwright.
8. **Распространение.** На старте — zip для режима разработчика (распакованное расширение). Затем Chrome Web Store в режиме «Доступ по ссылке», работает и в Edge, и в Яндекс Браузере. Токен берётся из `.env` при сборке и в git проекта не коммитится.

## Модель данных и ID (репозиторий `owl-smile-data`)

```
meta.json                       { "schema": 1 }
emotes/<Code>.json              { code, image: "img/<sha16>.webp", animated, w, h, author, createdAt }
badges/<badge-id>.json          { id, title, image: "img/<sha16>.webp", author }
paints/<paint-id>.json          { id, title, preset: "gradient|shimmer|glow|flicker|rainbow|solid", colors: ["#RRGGBB"...], angle?, speed? }
users/twitch/<login>.json       { badges: ["owl-founder"], paint: "gold-shimmer" }
users/vk/<nick>.json            { ... }
img/<sha16>.webp|gif            файлы картинок, имя = первые 16 hex SHA-256 содержимого (дедупликация, файл неизменяем)
```

- **Код смайла:** `^[A-Za-z0-9_]{3,25}$`, регистр учитывается, как в 7TV. Код уникален. Если код целиком в нижнем регистре и похож на обычное слово, показываем предупреждение: иначе «ok» станет картинкой.
- **ID иконки и эффекта:** slug `^[a-z0-9-]{2,32}$`, например `owl-founder` или `gold-shimmer`. В интерфейсе выбираются из списка, вручную их никто не вводит.
- **Ключ пользователя:** `платформа + ник в нижнем регистре`. На Twitch это логин (`data-a-user`), а не отображаемое имя.
- **Ограничения картинок:**
  - Смайл: исходник до 1 МБ; хранится высотой до 112 px (4x), показывается высотой 28 px.
  - Иконка: 72×72, показывается 18×18.
  - Статичные PNG/JPEG/WebP перекодируются в WebP через `OffscreenCanvas`.
  - Анимированные GIF/WebP сохраняются как есть после проверки сигнатуры и декодирования, лимит 1 МБ.

## Этапы

**Этап 0. Проверочные прототипы (1–2 дня), остальное зависит от них**
1. `isomorphic-git` в расширении: clone/fetch публичного репозитория и push с deploy-токеном на gitflic.ru. Проверить, достаточно ли прав deploy-токена для push и работает ли push из неглубокой копии. Если не работает: полная копия или аккаунтный токен отдельного бот-пользователя, который состоит только в этом проекте.
2. Twitch: селекторы сообщения, ника и текста; разрешает ли CSP `blob:`/`data:` в `img-src`; вставка в поле ввода (Slate) через `focus` + `execCommand('insertText')`; совместимость с 7TV/BTTV.
3. VK Live (`live.vkvideo.ru`): то же самое, что на Twitch: DOM, CSP, поле ввода, как получить ник автора.

**Этап 1. Каркас:** WXT-проект, zod-схемы, `.env`, `data-seed`, репозиторий в GitFlic (защита ветки, deploy-токен), `docs/setup.md`.

**Этап 2. Синхронизация (F1, F9):** `repo.ts` (fetchLatest/readTree), `background.ts` (обработчики событий, сравнение HEAD, загрузка недостающих картинок, чистка лишних), popup со статусом.

**Этап 3. Отображение смайлов на Twitch (F2):**
- `tokenizer` + `renderer`.
- MutationObserver вешается только на контейнер чата и заново подключается при SPA-навигации и в popout-чате.
- Обработанные узлы помечаются `data-owl`; ссылки, упоминания и ники не трогаем.

**Этап 4. Загрузка (F5, F6):** страница `manage`:
- drag-and-drop, предпросмотр, проверка кода;
- `image.ts`, затем `commitAndPush` (fetch → проверка, что код свободен → запись → commit → push → повтор при отказе) → локальная синхронизация;
- переименование и удаление смайлов;
- ник автора задаётся в настройках.

**Этап 5. Кнопка под чатом (F3):** пикер с поиском, недавними смайлами и кнопкой «+», которая ведёт на загрузку. Tab-автодополнение.

**Этап 6. Иконки и эффекты ников (F4, F7):**
- в `manage`: загрузка иконок, конструктор эффекта из пресетов с живым предпросмотром, назначение иконки или эффекта нику;
- `renderer` вставляет иконку перед ником и вешает класс `owl-paint-<preset>` + CSS-переменные.

**Этап 7. VK Live (F8):** адаптер `vklive.ts` по результатам этапа 0.3 и подключение core.

**Этап 8. Доработка и выпуск:**
- лимиты, понятные ошибки, офлайн-режим (работаем из кэша);
- необязательно: `gitflic-ci.yaml` с проверкой картинок и схем после push (нужен CI-агент);
- скрипт бэкапа `git clone --mirror`;
- zip-сборка, позже публикация в CWS «по ссылке».

## Риски

- **Push по HTTPS из расширения или права deploy-токена не сработают.** Резерв: токен отдельного бот-аккаунта, который состоит только в этом проекте. Это проверяется на этапе 0.1.
- **Вёрстка Twitch и VK Live меняется.** Все селекторы собраны в адаптерах, на каждую площадку есть e2e-фикстура.
- **Токен можно извлечь из расширения** — так задумано моделью «доверяем всем». Защита: токен ограничен проектом, force-push запрещён, есть бэкап-зеркало, история git.
- **Неглубокая копия растёт вместе с картинками.** При сотнях смайлов это единицы МБ, не критично. При необходимости можно периодически сбрасывать кэш копии.

## Проверка

- **vitest:**
  - tokenizer: пробелы, пунктуация, регистр, соседние смайлы, URL;
  - zod-схемы: отклоняют `"colors": ["red;background:url(...)"]` и чужие поля;
  - `image.ts`: файл `.exe`, переименованный в `.png`, отклоняется; большой GIF отклоняется; PNG превращается в WebP высотой ≤ 112.
- **Интеграция с git:** тестовый репозиторий в GitFlic. Два параллельных `commitAndPush` должны сохранить оба смайла (проверка retry). Повторный код должен давать ошибку «занято».
- **Playwright** (Chromium с `--load-extension`) на сохранённых HTML-фикстурах чатов Twitch и VK Live:
  - сообщение `hi CatJam` превращается в картинку;
  - иконка и класс эффекта стоят у нужного ника;
  - клик в пикере вставляет код в поле ввода.
- **Вручную:**
  - установить распакованное расширение на два ПК;
  - на первом загрузить смайл и назначить себе иконку и эффект;
  - на втором перезапустить браузер: синхронизация при старте, смайл, иконка и эффект видны в чате Twitch и VK Live;
  - выключить сеть: всё по-прежнему рендерится из кэша.
